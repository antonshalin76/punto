# Punto Switcher для Linux

Высокопроизводительная реализация Punto Switcher на C++20 для Linux.

Назначение сервиса — исправление раскладки EN/RU, регистра и опечаток в
X11-приложениях. Версия2.8.14 включает daemon, session helper, GNOME RU/EN
bridge и tray в одном пакете. Изменения и ограничения — в [RELEASE_NOTES.md](RELEASE_NOTES.md).
Следующие числа относятся к историческим прогонам; актуальный host checkpoint
приведён ниже и в [RESTORATION.md](RESTORATION.md).

35/35, GTK clipboard 1/1 и GTK/VTE/Chromium 352/352. Статический анализ:
две изменённые единицы прошли заново; результаты остальных 29 используются
только при совпадении исходников, заголовков и базы компиляции.
Один пакет 2.8.14 прошёл установку, обычное обновление и восстановление после
намеренного сбоя уже запущенной новой версии. Все 78 операций основного
GTK/Chromium/VTE-прохода завершились успешно; тот совмещённый проход затем
остановился на отмене GIO-запроса и остаётся неуспешным. На неизменившемся

операций за 1802,79 с, включая две пятиминутные паузы, без ошибок.

Исправления выполняются через X11 с проверками фокуса, раскладки и ввода.
Обычный GUI-путь использует ограниченный X11 replay по свежему выделению
приложения; адаптер внутри редактора для него не требуется. Это совместимое
редактирование, а не атомарная транзакция с подтверждением редактора.
Штатный AT-SPI через session helper различает поля одного окна и подтверждает
наблюдаемый диапазон. Для Chromium helper запрашивает расширенные свойства
документа стандартным API и ждёт появления поля в исходном бюджете операции;
Механизм не запускает экранный диктор и не добавляет флаги браузера. Приёмка
обычных установленных приложений без предварительного включения accessibility
ещё не завершена. Включение стандартной accessibility сохраняет общую
пользовательскую настройку GNOME. Пользователь одобрил её первичное включение;
при последующем отключении Punto не включает её снова после перезапуска
или обновления. Разрешение хранится в приватном persistent StateDirectory
`punto-session-bridge`; этот путь сохраняется при обновлениях. Экранный диктор
не требуется. Отсутствие доступного
provider в GUI остаётся безопасным отказом, а не разрешением исправить другое поле.
Для Chromium, запущенного до включения доступности, готовность ещё не подтверждена;
Punto не закрывает и не перезапускает браузер автоматически. Подробности — в
[проверке повторного включения](platform/evidence/autonomous-20261002/s2-g13-accessibility-reenable-disposition-20261004.md).
Native-адаптеры проверяются отдельно. Для VTE восстанавливается совместимое
исправление по свежей истории ввода; это не подтверждение содержимого PTY.

## Возможности

### Управление через трей (v2.4+)

Иконка `punto-tray` в системном трее позволяет:

- **Автокоррекция слов** — включает или выключает автоматические исправления;
  состояние подтверждается чтением daemon, ручные горячие клавиши остаются доступны.
- **Звук исправлений…** — открывает настройки звука смены раскладки.
- **Настройки...** — диалог GTK3 для параметров анализа, истории и звука
  (`~/.config/punto/config.yaml`). `max_rollback_words` ограничивает историю,
  в пределах которой может применяться отложенный результат анализа.
- **О программе** — окно со справкой/версией
- **Автозапуск** — desktop entry в `/etc/xdg/autostart/` идемпотентно
  активирует package-owned `systemd --user` unit; PID-файлы и raw PID signals
  не используются

### Автоматическое переключение (v2.1+, async в v2.5)

| Режим                       | Действие                                                  |
| --------------------------- | --------------------------------------------------------- |
| **АВТО** (при пробеле/табе) | Исправляет слово и при необходимости переключает раскладку |

#### Асинхронный pipeline анализа

- **Анализ в фоне**: классификация и чтение конфигурации не блокируют ввод.
- **Порядок слов**: результаты применяются по `task_id`, с сохранением
  разделителей, следующих слов и ещё не законченного хвоста.
- **Ограниченное исполнение**: перед исправлением проверяются контекст и
  ожидаемый текст. Физические события во время макроса буферизуются с лимитом;
  смена контекста отменяет ещё не выполненное действие.

Гибридный анализ (v2.6+):
- **Словари** (приоритет): если слово есть только в одной раскладке — решение однозначно
- **N-граммы**: используются только в случае, когда слово есть в обоих словарях (ambiguous)
- **Если слова нет в словарях** — анализ не предлагает смену раскладки.

#### Классификаторы v2.7 и CLI

- **Sticky Shift Fix**: автоматическое исправление ошибок регистра:
  - `ПРивет` → `Привет` (паттерн UU+L+: несколько заглавных в начале)
  - `кОЛБАСА` → `Колбаса` (паттерн L+U+: Caps Lock)
  - `GHbdtn` → `Привет` (комбинированное: смена раскладки + регистр)
  - **Смешанный регистр НЕ исправляется** (например, `СНиП`)
- **Typo Fix (beta, по умолчанию выключен)**: автоматическое исправление опечаток:
  - `ппривет` → `привет` (удаление дублей)
  - Использует Hunspell spell() для проверки правильности слова
  - Защита от ложных срабатываний: правильные слова не изменяются
- **CLI wrapper**: удобное управление сервисом:
  - `punto start` — запуск сервиса (backend + frontend)
  - `punto stop` — остановка сервиса
  - `punto restart` — перезапуск с перезагрузкой конфига
  - `punto status` — показать статус
  - `punto reset-learning` — очистить накопленные исключения автокоррекции
- **Новые настройки**:
  - `sticky_shift_correction_enabled` — вкл/выкл исправление регистра
  - `typo_correction_enabled` — вкл/выкл исправление опечаток
  - `max_typo_diff` — максимальное расстояние редактирования (1-2)

### Ручные горячие клавиши

| Комбинация           | Действие                                                                              |
| -------------------- | ------------------------------------------------------------------------------------- |
| **Pause**            | Инверсия раскладки текущего слова с сохранением разделителей |
| **Shift+Pause**      | Инверсия раскладки выделенного текста и переключение раскладки |
| **Ctrl+Pause**       | Инверсия регистра текущего слова |
| **Alt+Pause**        | Инверсия регистра выделенного текста |
| **LCtrl+LAlt+Pause** | Транслитерация выделения; приоритет над одиночными модификаторами |
| **Ctrl+Z**           | Отмена последнего исправления Punto в течение 2,5 с до следующего обычного ввода; иначе undo приложения |

### Примеры

```
ghbdtn[пробел]  →  [АВТО]  →  привет 
ghbdtn  →  [Pause]  →  привет
пРИВЕТ  →  [Ctrl+Pause]  →  Привет
[выделенное Privet]  →  [LCtrl+LAlt+Pause]  →  Привет
```

### Runtime

- **Асинхронный анализ** — анализ слова в фоне (worker pool), ввод не блокируется
- **Строгая упорядоченность** — результаты анализа учитываются по порядку слов (`task_id`)
- **Один исполнитель** — `WordEditor` обслуживает слова, выделение и отмену;
  `EventLoop` владеет историей и порядком применения, `X11Session` — сессией,
  `ClipboardManager` — передачей clipboard, `UndoDetector` — обучением.
- **Телеметрия** — `STATS` показывает средние `avg_queue_us`,
  `avg_analysis_us`, `avg_macro_us` и `avg_macro_payload_bytes`; периодические
  агрегаты очереди и анализа также доступны в `journalctl -u udevmon -f`.
  Размеры внутренней истории и сырых очередей доступны только тестовой сборке,
  поэтому production-схема IPC остаётся совместимой с CLI и tray
- **Auto-budget worker pool** — при нескольких `punto-daemon` analysis pool
  делится по числу daemon-процессов, обнаруженных при старте каждого процесса.
  После hotplug/hot-unplug перезапустите `udevmon`, чтобы пересчитать бюджет
- **Primary control-plane** — только один `punto-daemon` держит `/var/run/punto.sock`; secondary daemons синхронизируют `RELOAD`/`SET_STATUS` через shared state в `/var/run/punto-control.state`
  Повторный `SET_STATUS` с уже действующим значением подтверждает новое поколение
  статуса, но не сбрасывает контекст набранного слова. Реальная смена режима и
  конфигурации отменяет прежние операции; команда, поступившая во время макроса,
  сохраняет консервативную отмену.

Также доступны возможности v2.4:
- **Управление через трей** — `punto-tray` (GTK3 + AppIndicator/Ayatana),
  подтверждённый статус автокоррекции и настройки
- **Layout snapshot** — читается подтверждённым X11 probe; при исправлении
  daemon запрашивает целевой EN/RU source через аутентифицированную цепочку
  `DesktopLayoutClient` → `punto-session-bridge` → GNOME Shell extension и
  продолжает только после подтверждения source и XKB-группы
- **Настройки + bounded reload** — чтение пользовательского конфига выполняется
  вне input-thread; IPC принимает задачу без остановки passthrough
- **IPC через Unix Socket** — `/var/run/punto.sock` (GET_STATUS, SET_STATUS, RELOAD, STATS)
- **Управление обучением** — `CLEAR_EXCLUSIONS` очищает скрытые исключения,
  накопленные после отмен автокоррекции; secondary daemons перечитывают общий
  файл при следующей синхронизации.
- **Анализ раскладки** — словарь-first; N-граммы используются только для
  ambiguous слов (есть в обоих словарях).
- **Звук** — асинхронно после завершённой смены раскладки, если включён в конфиге.
- **Clipboard** — один владелец pending-paste сохраняет прежние данные до
  временной публикации, включая неопределённый результат Set и отказы до Ctrl+V.
  Восстановление разрешается
  только после завершения макроса и его внутреннего cleanup. Для отправленного
  paste ожидание первого receipt ограничено 2 секундами; последующие text-
  запросы того же клиента продлевают 250 мс quiet-grace, но не более 1 секунды
  после receipt. Эти сроки не разрешают заменить payload ещё работающего
  макроса. Неудачное восстановление повторяется только в ограниченном lifecycle;
  после его истечения остаются сохранённые данные без права будущей публикации.
  Чужой owner или потеря доказанной непрерывности прекращает восстановление.
  Переносимые text/HTML/PNG/JPEG/MIME представления сохраняют исходные target,
  type, format и bytes, включая NUL и выровненные 16/32-битные данные. Общий
  предел snapshot — 64 data-targets и 4 MiB; INCR имеет ограниченные chunk/transfer
  budgets. TARGETS/TIMESTAMP создаются заново; identity внешнего владельца не
  восстанавливается. Прямая отправка клавиш сохраняет CLIPBOARD полностью.
  Автоматический Tab передаёт целый текст через clipboard. Новая clipboard-зависимая
  операция может дождаться штатного восстановления предыдущего Delivered
  receipt в пределах собственного исходного срока. Pending/Invalid receipt
  не даёт такого допуска.
  Идентичность клиента — выделенный X11 resource-id base; абсолютный лимит
  receipt также ограничивает редкий случай повторного использования base X-сервером.

## Production Checklist

- IPC socket `/var/run/punto.sock` рассчитан на режим `root:punto` с правами `0660`.
- Shared control-plane state `/var/run/punto-control.state` и lease `/var/run/punto-control.lock` также создаются с `root:punto` и служат для failover primary daemon.
- После захвата lease новый primary сначала применяет последний безопасный
  state snapshot. Если прежний user-path больше не разрешён текущей desktop-
  сессией, выполняется reload стандартного config этой сессии; если явно
  сохранённый path исчез, допускается только успешно загруженный fallback.
  Пока ни один разрешённый config не применён, процесс остаётся secondary,
  не создаёт primary IPC и не повышает generation. Успешный failover всегда
  публикует строго следующее поколение.
- Пользователи tray и локальных IPC-клиентов должны состоять в группе `punto`.
- Tray поддерживается в графической сессии с `systemd --user` версии 249.10 или
  новее. Desktop entry и CLI управляют только статическим package-owned unit
  `punto-tray.service`; отсутствие user manager выдаёт `WARN tray-unavailable`
  и не меняет состояние уже здорового backend. User manager должен получить
  `DISPLAY`/`WAYLAND_DISPLAY` и `XAUTHORITY` от desktop session; это штатно для
  GNOME, а в иных окружениях переменные нужно импортировать в user manager до
  запуска unit. Несколько одновременных GUI-сессий одного UID разделяют один
  tray unit и не являются поддержанной конфигурацией.
- Периодический `STATS` tray выполняет в single-flight background worker:
  недоступный IPC не замораживает GTK main loop и не накапливает запросы.
- При старте daemon доверяет только `/etc/punto/config.yaml`; пользовательский
  конфиг становится доступен после подтверждения активного desktop-сеанса.
- Root daemon читает Xauthority активной сессии только из закреплённого
  regular-файла владельца с правами без group/world write. Для локального X11
  точная запись display имеет приоритет, но поддерживается и используемая GDM
  запись с пустым номером display; внутри одного класса действует порядок
  `FamilyLocal` → `FamilyLocalHost` → `FamilyWild`. Повреждённый файл
  отклоняется целиком, а XCB выполняет одну bounded auth-попытку без перебора
  cookies после отказа сервера.
- `RELOAD <path>` разрешён только для `/etc/punto/`, `$XDG_CONFIG_HOME/punto/`
  и `~/.config/punto/`. Путь открывается относительно закреплённого корневого
  дескриптора; обход от `/` не следует ни одному symlink-компоненту, а подмена
  каталога не позволяет выйти из закреплённого root: читается уже открытый
  inode либо операция отклоняется. Чтение и YAML parse выполняются в
  single-flight background loader: команда возвращает `OK Scheduled`,
  параллельный пользовательский reload — `ERROR Config reload in progress`.
  Смена подтверждённой X11-сессии создаёт внутреннее поколение reload: если
  loader занят, последний session intent выполняется после завершения старой
  работы, а результат прежней сессии не может быть опубликован.
- `echo "STATS" | nc -U /var/run/punto.sock` возвращает runtime-счётчики
  конкретного демона. При нескольких устройствах проверяйте также
  `/run/punto-<PID>.sock`: основной socket не суммирует ввод других демонов.
- В `STATS` видны `daemon_peers`, `analysis_mode`, `log_dropped`,
  `text_mutation=x11`, текущий `enabled` и отдельный `configured_enabled`.
  `enabled` управляет автокоррекцией, а не ручными действиями. Сам по себе
  здоровый IPC не доказывает изменение текста в приложении.
  `config_pending`, `config_generation` и `config_result`
  (`none|ok|error`) показывают завершение асинхронного reload.
  `learning_generation`, `learning_completed_generation` и
  `learning_failed_generation` показывают долговечность операций обучения, а
  `daemon_epoch` связывает подтверждение `CLEAR_EXCLUSIONS` с тем же процессом
  даже при failover primary-daemon.
- Словари загружаются в отдельном потоке после безопасного запуска passthrough,
  signal-fd и диагностического IPC. Пока immutable snapshot не готов, `STATS`
  показывает `analysis_health=degraded` и `worker_threads=0`; ввод при этом
  проходит без блокировки. Один файл ограничен 16 MiB, общий объём —
  32 MiB, строка — 4096 байт, загрузка — 2 000 000 строк.
- Диагностические сообщения демона уходят в syslog/journald; уровень задаётся через `logging.level`.
- При отсутствии, повреждении или превышении лимита словарей daemon публикует
  диагностическое состояние, затем завершает старт с кодом 2 и удаляет свой
  IPC socket вместо перехода в бессрочный degraded-режим.
- Для CI используйте `./build-deb.sh --non-interactive --skip-runtime-installs`.
  Состав пакета детерминирован: tray обязателен по умолчанию; явный
  `--without-tray` убирает tray. Обычный пакет не содержит GTK-модуль редактора
  или его автозагрузку; браузерное расширение также не требуется. Без внешнего
  `SOURCE_DATE_EPOCH` применяется закреплённая дата сборки
  (`1788566400`, 2026-09-05 UTC), а заданное окружением значение позволяет
  независимо воспроизвести сборку с другой закреплённой датой.

## Known Limitations / Threat Model

- Для исправлений со сменой раскладки требуется GNOME Shell 46 в X11-сеансе,
  включённое package-owned расширение и ровно два XKB-источника без variants:
  `us` (EN, группа 0) и `ru` (RU, группа 1). Wayland, KDE, другие версии GNOME
  и иные карты источников для layout-correction не поддерживаются. При
  неизвестном фокусе, отсутствующем bridge или неподтверждённой сессии текст
  не изменяется.
- Для исправления требуется свежее наблюдение фокуса, группы и locked modifiers;
  задержавшийся ответ от старого контекста не разрешает действие.
- При logout или невалидном конфиге нового desktop-пользователя сохраняется
  последний успешно проверенный config snapshot; исправленный конфиг
  применяется командой `RELOAD` или следующим
  успешным session reload.
- Maintainer scripts не подключаются к активным user managers и не запускают,
  не перезагружают и не останавливают пользовательские units. Новые статические
  units и XDG autostart entries подхватываются при следующем графическом входе.
  Перезапуск tray/session bridge и включение расширения относятся только к
  отдельной контролируемой активации с явным rollback, а не к `dpkg configure`.
  Исключение для прямого обновления с 2.8.5: его старый `prerm upgrade` до
  установки нового пакета выполняет `systemctl stop udevmon`. Поэтому такое
  обновление нельзя выполнять как обычный `dpkg -i` на работающей машине:
  нужен заранее проверенный план контролируемой активации и восстановления
  `udevmon`, включая путь отката. Архив 2.8.5 также оставляет старый
  `udevmon.yaml` с `/usr/local/bin/punto-daemon` и tray-autostart; прямое
  неинтерактивное обновление может остановиться на вопросе о conffile.
  Миграция этих точных legacy-файлов и запуск одного нового pipeline требуют
  отдельной проверяемой процедуры; новый `postinst` их не заменяет.
  Переход на `--without-tray` помечает устаревший системный XDG autostart
  conffile как `remove-on-upgrade`, не вмешиваясь в текущую desktop-сессию.
- Compose/dead keys/AltGr пока не поддерживаются полноценно и считаются отдельной инициативой.
- Обычный GUI-путь не требует расширения браузера или адаптера редактора.
  Ручная команда выбирает диапазон слева от курсора средствами приложения,
  проверяет свежую PRIMARY identity, стабильность выделения и X11-контекст.
  Если первая native-единица содержит только разделители, допускается ещё одна
  проверенная единица, не более двух. Для пропущенного пунктуационного префикса
  физический hint может задать конечное число шагов Shift+Left. Перед каждым
  следующим шагом требуется свежий стабильный диапазон, точно совпадающий с
  заранее рассчитанным UTF-8-суффиксом. Число шагов не увеличивается; несовпадение
  или новый диапазон прекращают попытку до следующего шага. Только полное
  совпадение разрешает преобразование. Автокоррекция и отмена требуют точного
  ожидаемого текста. Прямая отправка клавиш не меняет CLIPBOARD.
  Принятие последовательности X-сервером не подтверждает её завершение
  редактором: программная смена поля с возвратом и произвольные отложенные IM
  commits не имеют доказанной атомарности. Для автоматического Tab после
  desktop-preflight и повторной проверки PRIMARY отправляется целая замена
  через paste, затем один исходный Tab. В проверенном GTK Entry callback
  сохраняет исходный widget и всю строку, поэтому вложенная обработка событий
  не направляет оставшиеся буквы в следующее поле. Clipboard receipt не является
  подтверждением редактора. Срок выпуска Tab — не срок завершения callback.
  Если полный переносимый snapshot недоступен, исправление на Tab отклоняется
  до изменения текста и clipboard, а исходный Tab передаётся приложению.
  Action/resource targets, неизвестные non-MIME targets и malformed/oversized
  данные не копируются; потенциально изменяющие состояние targets не опрашиваются.
- Chromium может сохранять PRIMARY после снятия видимого выделения.
  Команды преобразования выделения требуют непустой фактический диапазон
  редактора с совпадающим текстом; сохранённый PRIMARY сам по себе не даёт
  разрешения на запись. В текущем Chrome выделение с non-BMP emoji может
  возвращаться через AT-SPI как пустой диапазон при непустом DOM-выделении.
  Такое несогласованное выделение безопасно отклоняется; новое корректно
  наблюдаемое выделение работает без перезапуска сервиса.
  Повторное исправление слова разрешено, если это точное служебное выделение
  предыдущего успешного исправления Punto в том же фокусе и X11-сеансе.
  Если клиент уже не отдаёт payload, непрерывность подтверждается неизменной
  XFixes identity: owner, selection timestamp и поколение owner должны точно
  совпасть с receipt. Проверка проходит только до ограниченной X11-границы
  наблюдения; неполная очередь событий считается отказом, а не совпадением.
  Новое читаемое выделение пользователя и неизвестное происхождение PRIMARY
  разрешения не дают. Узкое исключение для восстановления: явный ответ NONE
  от того же owner и clipboard-соединения в сохранённом фокусе/сеансе допускает
  подготовку нового диапазона только после действительно нового физического
  ввода. Текущая unreadable identity становится baseline; старый payload не
  разрешает запись. Без свежего ввода безопасный отказ сохраняет lineage, а
  timeout или malformed payload не дают этого дополнительного разрешения.
  Сброс анализа, настроек или истории
  не удаляет проверенную служебную identity: она разрешает только preflight,
  а новый диапазон всегда выделяется и подтверждается заново. Поэтому
  старое выделение из другого поля не переносит разрешение на запись. Ручной
  запрос в другом доказанном child с пустым реальным выделением может подготовить
  новый диапазон; старая PRIMARY identity служит только baseline. Невыполненная
  failed-lineage обязанность по-прежнему требует нового физического ввода.
  Receipt нового успешного исправления имеет
  отдельный lifecycle: штатное завершение ожидания по бюджету сохраняет его, а
  смена focus, pointer, locks, identity или X11-сеанса отзывает.
- Принятая desktop-комбинация смены раскладки отслеживается отдельным состоянием
  до наблюдения целевой группы. Если группа меняется непосредственно перед, во
  время или сразу после cleanup, Punto согласует наблюдаемую раскладку и
  допускает следующее исправление без ручного переключения. Неизвестный переход
  либо расхождение desktop source и XKB остаются fail-closed.
- Повторный ввод слова вместе с сохранённым хвостом ограничен 128 символами
  (до 256 байт UTF-8). Обычная фаза макроса ограничена 300 мс, подтверждение
  каждого перехода раскладки — 1 с, а вся операция — 3,5 с. В обычном X11
  клиенте новая группа должна быть стабильна 5 мс. После наблюдаемого возврата
  фокуса или отпускания собственной desktop-комбинации Punto ждёт 250 мс.
  Исходное GUI-выделение должно оставаться неизменным ещё 30 мс; совпадение
  текста в том же клиенте не считается подтверждением того же диапазона.
  Наблюдаемое GUI-выделение и результат ограничены 4096 байтами UTF-8;
  подтверждение диапазона использует тот же предел, без урезания до 256 символов.
  После внутренних ожиданий диапазон повторно проверяется перед первой
  записывающей клавишей, а для paste — перед публикацией CLIPBOARD, после
  допуска receipt и непосредственно перед Ctrl+V. Это проверка допуска,
  не атомарная блокировка редактора. Уже начатая запись не маскируется как отказ.
  `max_rollback_words` жёстко ограничивает историю отката. Наблюдение и анализ
  живут отдельно от неё, поэтому вытеснение старой записи не завершает и не
  теряет текущий `(limit + 1)`-й кандидат. Лимит длины применяется отдельно.
  Неподдерживаемое действие отклоняется;
  при невозможности немедленной отмены Punto до начала действия используется
  обычный undo приложения.
- В терминале явные команды регистра, раскладки и транслитерации выделения
  вставляют преобразованный однострочный текст в текущую строку ввода через
  Ctrl+Shift+Insert (CLIPBOARD в VTE, независимо от RU/EN). Они не заменяют scrollback-выделение и не удаляют уже набранный
  текст. Нужны стабильная PRIMARY identity и text-only CLIPBOARD; управляющие
  символы, переносы строк и некорректный UTF-8 отклоняются до преобразования.
  Восстанавливается прежний plain text CLIPBOARD, не identity прежнего owner.
  Receipt подтверждает передачу payload клиенту, не завершение записи в PTY.
  После отправленной вставки отказ смены раскладки остаётся PartialFailure;
  текст не откатывается и старая вставка не повторяется автоматически.
  Ручное исправление слова, автокоррекция и немедленный undo терминала работают
  по свежей физической истории ввода, как режим совместимости. Это не чтение
  текущей строки PTY и не подтверждение её содержимого редактором. Перед
  удалением слова допускается передача UTF-8 через CLIPBOARD; успешная операция
  требует завершённого восстановления прежнего содержимого буфера. Навигация,
  отправка строки, посторонние сочетания, смена поля/сессии, переполнение и
  неоднозначный контекст прекращают эту историю. Отклонённый служебный undo
  не использует запасной Ctrl+Z, который мог бы отправить SIGTSTP приложению.
- Демон работает в root-контексте и читает `/proc/<pid>/environ` только для процессов активного GUI-пользователя.
- Логи должны содержать только типы IPC-команд и агрегированные счётчики, а не содержимое набранных слов.

Отмена автоматического исправления или три Backspace вскоре после него обучают
исключениям. Ручное исправление остаётся доступно. `/etc/punto/undo_exclusions.txt`
читается и атомарно сохраняется в фоне с блокировкой между процессами: до
1024 слов по 63 байта, файл до 65536 байт. Существующие печатные ASCII-записи,
включая знаки раскладки и регистр, сохраняются без потери слов. Новое обучение
использует символы физических клавиш US, в том числе `;`, `[`, `]`, `,` и `.`.
Принятое исключение сразу действует
в памяти; ошибка долговременной записи диагностируется отдельно. Файл не должен
быть symlink или доступным для записи посторонним пользователям. Требуются
владелец `root:root`, одна жёсткая ссылка и права `0600`. При обновлении пакет
переводит только обычный файл `root:root 0644` с одной ссылкой в `0600`,
не меняя его байты; небезопасные файлы оставляет нетронутыми с предупреждением.
Служебный атомарно публикуемый reset-marker хранит boot-scoped монотонную
отметку последнего reset:
запись secondary-daemon, принятая до подтверждённого `CLEAR_EXCLUSIONS`, не
может восстановить уже очищенное исключение после освобождения `flock`.

## Установка

В новом кандидате `punto start/restart` сначала запускает обязательный
`punto-session-bridge.service` и проверяет desktop bridge через невносящий
изменений typed `ReadState`. При отсутствии helper или готового bridge команда
возвращает `ERROR bridge-unavailable`, не запуская и не перезапуская backend.
Это намеренный отказ, а не подтверждение работоспособности установленного2.8.13.
Остановка helper допустима только после подтверждённой остановки backend.
Tray остаётся необязательным. Проверка готовности desktop не заменяет проверку
реального ввода и не обходит авторизацию daemon/helper.

### Способ 1: Сборка и установка deb-пакета (рекомендуется)

`build-deb.sh`:
- проверит зависимости;
- соберёт daemon, bridge и `punto-tray`; отсутствие GTK3/AppIndicator dev-пакетов
  завершает default-сборку явной ошибкой;
- соберёт deb-пакет;
- не будет устанавливать или изменять пакеты в системе сборки.

```bash
git clone https://github.com/antonshalin76/punto.git
cd punto
./build-deb.sh --non-interactive --skip-runtime-installs
sudo dpkg -i "punto-switcher_2.8.14_$(dpkg --print-architecture).deb"
```

Команда `dpkg -i` здесь относится к чистой установке. Для обновления с
2.8.5 используйте только проверенный сценарий с явной активацией и откатом:
старый пакет останавливает `udevmon` до настройки нового. Проверка в
изолированном корне подтверждает сохранность конфига, но не заменяет
проверку восстановления ввода на установленной системе.

Готовые `.deb` и `SHA256SUMS` публикуются в GitHub Releases и не хранятся в
дереве исходников. CI проверяет `lintian` только для артефакта текущей версии и
архитектуры, а не для произвольных старых пакетов в рабочем каталоге.

### Способ 2: Сборка из исходников

#### Зависимости

> Примечание: `build-deb.sh` рассчитан на Debian/Ubuntu. В CI и автоматизации
> используйте `--non-interactive`; `--skip-runtime-installs` разрешает собрать
> пакет без установки runtime-зависимостей, а `--without-tray` — явно убрать
> tray. GTK-модуль редактора не входит в обычный пакет. Наличие dev-пакетов
> больше не меняет состав молча.

```bash
# Ubuntu/Debian (минимум для сборки punto)
sudo apt install build-essential cmake pkg-config libyaml-cpp-dev \
  libglib2.0-dev libjson-glib-dev libsystemd-dev libssl-dev libxcb1-dev \
  libxcb-xkb-dev libxcb-xfixes0-dev \
  libxcb-xtest0-dev libxcb-xinput-dev libxcb-res0-dev libxkbcommon-dev libxau-dev \
  libhunspell-dev libgtk-3-dev \
  interception-tools util-linux

# Для изолированных CLI/package/daemon/GTK contract-тестов
sudo apt install apparmor bubblewrap busybox-static strace util-linux \
  gjs python3-gi gir1.2-vte-2.91 xauth xclip xdotool xvfb

# Только для default-пакета с tray (AppIndicator/Ayatana)
sudo apt install libayatana-appindicator3-dev

# Runtime-словари: daemon требует рабочие EN и RU словари и завершает старт,
# если ни один поддерживаемый источник для языка не найден. .deb устанавливает
# hunspell-en-us и hunspell-ru как зависимости.
sudo apt install hunspell hunspell-en-us hunspell-ru

# Опционально: дополнительный расширенный английский словарь
sudo apt install wamerican-huge

```

Сетевые sandbox-тесты используют private user/network namespaces Bubblewrap и
не имеют fallback на сеть хоста. На GitHub-hosted Ubuntu 24.04 workflow
устанавливает CI-only AppArmor-профиль, разрешающий `userns` только исполняемому
файлу `/usr/bin/bwrap`; глобальный sysctl безопасности не отключается.
Xvfb сообщает готовность через `-displayfd`, а package-test spies вызывают
инструменты из заявленных Debian providers по точным путям `/usr/bin/*`.

#### Сборка

```bash
git clone https://github.com/antonshalin76/punto.git
cd punto
./build-deb.sh
sudo dpkg -i punto-switcher_2.8.14_amd64.deb
```

#### Ручная сборка без пакета

```bash
cd cpp
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build . -j$(nproc)
sudo install -m 0755 punto /usr/bin/punto-daemon
sudo cp ../../config.yaml /etc/punto/
```

Этот минимальный ручной путь является daemon-only: он не создаёт проверяемый
`/etc/punto/runtime-gid`, не устанавливает CLI/tray user unit и поэтому не
обещает IPC. Для полного контракта `0660 root:punto`, CLI и tray используйте
`.deb`, чей maintainer script атомарно публикует runtime GID. Не создавайте этот
файл через world-writable каталог или ослабленные права.

### Настройка udevmon

Текущие maintainer scripts не перезаписывают `/etc/interception/udevmon.yaml`
и не управляют чужим `udevmon.service`; исключение при переходе с 2.8.5
описано выше, поскольку выполняется его старый `prerm`. В сервисе могут быть другие
interception-пайплайны. Создайте или вручную объедините конфигурацию
`/etc/interception/udevmon.yaml`; после установки `.deb` пример находится в
`/usr/share/doc/punto-switcher/examples/udevmon.yaml` (в исходниках —
`udevmon.yaml`):

```yaml
- JOB: "interception -g $DEVNODE | /usr/bin/punto-daemon | uinput -d $DEVNODE"
  DEVICE:
    LINK: .*-event-kbd
    EVENTS:
      EV_KEY: [KEY_A, KEY_B, KEY_C, KEY_D, KEY_E, KEY_F, KEY_G, KEY_H, KEY_I, KEY_J, KEY_K, KEY_L, KEY_M, KEY_N, KEY_O, KEY_P, KEY_Q, KEY_R, KEY_S, KEY_T, KEY_U, KEY_V, KEY_W, KEY_X, KEY_Y, KEY_Z, KEY_1, KEY_2, KEY_3, KEY_4, KEY_5, KEY_6, KEY_7, KEY_8, KEY_9, KEY_0, KEY_MINUS, KEY_EQUAL, KEY_BACKSPACE, KEY_TAB, KEY_ENTER, KEY_LEFTSHIFT, KEY_RIGHTSHIFT, KEY_LEFTCTRL, KEY_RIGHTCTRL, KEY_LEFTALT, KEY_RIGHTALT, KEY_COMMA, KEY_DOT, KEY_SLASH, KEY_SEMICOLON, KEY_APOSTROPHE, KEY_LEFTBRACE, KEY_RIGHTBRACE, KEY_BACKSLASH, KEY_GRAVE, KEY_SPACE, KEY_PAUSE, KEY_LEFT, KEY_RIGHT, KEY_UP, KEY_DOWN, KEY_HOME, KEY_END, KEY_PAGEUP, KEY_PAGEDOWN, KEY_INSERT, KEY_DELETE]
```

При обновлении существующей установки проверьте, что фильтр `LINK` добавлен в
рабочий `/etc/interception/udevmon.yaml`, и затем явно выполните
`sudo systemctl restart udevmon`. Пакет не меняет этот общий системный файл и
не перезапускает сервис автоматически.

### Запуск

#### С помощью CLI (рекомендуется)

```bash
punto start     # Запуск сервиса (backend + frontend)
punto status    # Проверка статуса
punto restart   # Перезапуск (после изменения конфига)
punto reset-learning # Очистить исключения, накопленные после отмен исправлений
punto stop      # Остановка
```

Команды `start`, `restart` и `stop` вызывают `sudo -n systemctl`: нужен уже
активный sudo-сеанс или узкое правило `NOPASSWD` только для `udevmon.service`.
При отсутствии такого доступа CLI завершается с `ERROR service-error` и не
показывает интерактивный запрос пароля.
Если `udevmon` уже активен, `punto start` только проверяет существующий IPC и
не перезапускает общий сервис при `denied`, timeout или ошибке протокола;
явный перезапуск выполняет только команда `punto restart`.

#### Вручную через systemd

```bash
sudo systemctl enable udevmon
sudo systemctl start udevmon
```

## Настройка

Конфигурация по умолчанию: `/etc/punto/config.yaml`

Пользовательский конфиг (получает приоритет после подтверждения активного
desktop-сеанса): `~/.config/punto/config.yaml`

```yaml
# Физическая комбинация GNOME, которую EventLoop распознаёт как смену контекста;
# программное исправление выбирает source через session bridge
hotkey:
  modifier: leftctrl   # leftctrl, rightctrl, leftalt, rightalt, leftshift, rightshift, leftmeta, rightmeta
  key: grave           # физическая клавиша над Tab (` / ~)

# Раздел delays удалён в v2.8.0 и строгой схемой не принимается.
# Автокоррекция слова при нажатии пробела/таба
auto_switch:
  enabled: true        # Начальное состояние автокоррекции
  threshold: 3.5       # Порог срабатывания (разница скоров)
  min_word_len: 2      # Минимальная длина слова для анализа
  min_score: 5.0       # Минимальный скор для уверенного решения
  max_rollback_words: 5 # Максимальная история отложенного исправления
  sticky_shift_correction_enabled: true
  typo_correction_enabled: false # Beta: включается пользователем явно
  max_typo_diff: 2

# Звук завершённой смены раскладки
sound:
  enabled: true

logging:
  level: info

runtime:
  analysis_threads: 0              # 0 = auto-budget, >0 = фиксированное число на daemon
  max_analysis_threads_per_daemon: 4
```

Punto не создаёт системную комбинацию: `hotkey` должен совпадать с настройкой
переключения источника ввода GNOME, чтобы физическая смена раскладки корректно
сбрасывала историю и pending-кандидаты. Для GNOME текущую настройку
можно проверить командой
`gsettings get org.gnome.desktop.wm.keybindings switch-input-source`.
Для дефолта `leftctrl+grave` GNOME должен распознавать именно физическую клавишу
над Tab. В Mutter/GNOME 46 аппаратно-независимое имя этой клавиши —
`<Control>Above_Tab` (без завершающего `>`). Не добавляйте
`<Control>Cyrillic_io`: GNOME 46 считает
это значение невалидным и не регистрирует его. После изменения binding
обязательно проверьте два последовательных перехода EN→RU→EN; один успешный
переход или один лишь readback `gsettings` не доказывает рабочую конфигурацию.

#### GNOME 46 X11: зависание ввода после смены источника

В GNOME Shell 46 на X11 существует воспроизводимый отказ штатного пути смены
источника: сам источник меняется, но физическая клавиатура остаётся замороженной
для приложений. Он проявляется и через меню GNOME, то есть не создаётся Punto.
В более новой реализации GNOME X11-only вызовы freeze/release удалены как
ненужные. Пакет содержит узкое opt-in расширение для GNOME 46 X11. Оно безопасно
обходит старый freeze/release callback и является единственным production-
владельцем выбора `us`/`ru` source по запросу `punto-session-bridge`; daemon не
использует XTest для программного переключения и не меняет binding, XKB или IBus.

После установки пакета войдите в сеанс заново, затем включите расширение:

```bash
gnome-extensions enable punto-input-source@antonshalin76
gnome-extensions info punto-input-source@antonshalin76
systemctl --user status punto-session-bridge.service
```

На Wayland, другой основной версии Shell, изменённом API или при наличии чужой
обёртки расширение остаётся неактивным. Отключение восстанавливает исходный
метод, только если им всё ещё владеет расширение:

```bash
gnome-extensions disable punto-input-source@antonshalin76
```

### Переключение раскладки

Поддерживаемый production-контракт — GNOME 46 X11, ровно два XKB-источника
`us`/`ru` без variants, включённое расширение и активный
`punto-session-bridge.service`. При исправлении daemon запрашивает точный
целевой source через private peer D-Bus и ждёт согласованного подтверждения
GNOME source и XKB-группы. Отсутствующий helper/extension, иной набор source,
заблокированная сессия или расхождение GNOME/XKB приводят к fail-closed отказу
до изменения текста. Punto не синтезирует desktop hotkey и не меняет системную
настройку через `gsettings`/`setxkbmap`; `hotkey` нужен для распознавания
физического пользовательского переключения и сброса устаревшего контекста.

После изменения можно применить настройки без перезапуска:

```bash
# Через tray-приложение: диалог настроек -> "Сохранить"
# Сохранение планирует bounded reload; применение подтверждает следующий STATS:
# config_pending=0 config_result=ok

# Или через командную строку:

echo "RELOAD" | nc -U /var/run/punto.sock
# OK Scheduled; завершение: STATS config_pending=0 config_result=ok

# Включить/выключить автоматические исправления (ручные остаются доступны):
echo "SET_STATUS 1" | nc -U /var/run/punto.sock
# OK ENABLED
echo "SET_STATUS 0" | nc -U /var/run/punto.sock
# OK DISABLED

# Проверить текущий статус:
echo "GET_STATUS" | nc -U /var/run/punto.sock

# Или перезапуском сервиса:
sudo systemctl restart udevmon
```

## Решение проблем

### Клавиатура не работает после установки

```bash
sudo systemctl stop udevmon
```

### Проверка работы сервиса

```bash
sudo systemctl status udevmon
sudo journalctl -u udevmon -f
```

### Инверсия выделенного текста не работает

Проверьте X11-сеанс, US/RU группы, фокус и актуальное выделение PRIMARY.
Обычные GTK/Chromium операции не требуют редакторского адаптера. Причину отказа
сверяйте с `rejection_stage` в журнале: неизвестный диапазон, смена контекста
или неподтверждённая раскладка запрещают изменение текста. Не повторяйте
операцию вслепую. GNOME bridge системной раскладки — отдельный компонент.

### Автопереключение не срабатывает

Проверяйте отдельно готовность daemon и результат в текстовом поле:

1. Проверьте, что `auto_switch.enabled: true` в конфиге.
2. Убедитесь, что установлены hunspell словари:

```bash
sudo apt install hunspell-en-us hunspell-ru
```

3. Проверьте `STATS`: ожидаются `text_mutation=x11 enabled=1`, готовые словари
   и подтверждённый X11-сеанс. `configured_enabled=1` не отменяет runtime-выключение
   через трей. При необходимости выполните `SET_STATUS 1`.
4. Если отдельные слова перестали исправляться после отмен или серии Backspace,
   выполните `punto reset-learning`. Команда очищает общий список исключений,
   не меняя YAML-настройки.
5. В отдельном пустом текстовом поле при EN введите `ghbdtn` и пробел:
   ожидается `привет `. Проверьте Pause и немедленную отмену Ctrl+Z.

### Переключение раскладки не срабатывает

Нужны US первой и RU второй группой. Проверьте, что комбинация обычного ручного
переключения настроена средствами рабочего стола и в точности совпадает с
`hotkey` в YAML. Punto использует эту комбинацию, но не меняет системную карту
и не создаёт desktop binding самостоятельно.

## История изменений

### v2.8.14 — стабильность коррекций и безопасное восстановление

- Исправлено бессрочное блокирование последующих RU/EN-коррекций, если
  приложение приняло `Ctrl+V`, но не запросило clipboard payload. Обычные
  исправления слов снова допускаются после короткого защитного интервала;
  selection и clipboard-зависимые операции остаются заблокированы до реального
  запроса, смены владельца clipboard или X11-сессии.
- Физический `Ctrl+Z` не перехватывается Punto, пока ожидается поздний paste;
  синтетический native undo в этом состоянии запрещён.
- Подготовленное GTK/Chromium-выделение отслеживается от исходного PRIMARY
  baseline. Первый или промежуточный отказ XTest сворачивает только причинно
  созданное Punto выделение и не затрагивает новое выделение пользователя.
- Confirmation и cleanup получили отдельные фазовые бюджеты внутри общего
  лимита операции; последующая коррекция восстанавливается без перезапуска.
- E2E-проверки layout bridge теперь различают видимое изменение текста и
  завершение dispatch, не принимая занятый основной цикл за отказ IPC.
- Ошибка повторного чтения XKB после подтверждённой смены раскладки теперь
  прекращает коррекцию до обращения к XInput2 через закрытое XCB-соединение.
  Следующее слово обрабатывается тем же процессом после нового ввода.
- Descriptor пользовательского session bridge открывается неблокирующе и
  проверяется как обычный файл до подключения. FIFO без writer больше не может
  остановить обработку клавиатуры.
- D-Bus client обрабатывает входящие сообщения ограниченными порциями, между
  которыми проверяет завершение, отмену и deadline. Повторная отправка одной
  операции `Switch` при восстановлении запрещена.
- GNOME extension принимает фактическую форму аргументов, которую GJS передаёт
  обработчикам `Gio.DBusExportedObject.wrapJSObject`. Production-адаптер
  проверяется на приватной session bus для `BindHelper`, `GetState`, `Switch`
  и `GetOperation`, включая отказ по версии/digest, точность `uint64` и
  отсутствие повторной активации source при восстановлении операции.

### v2.8.13 (кандидат) — GNOME и rich clipboard hardening

- На подтверждение каждого перехода раскладки отведено до 1 с при непрерывной
  проверке X11-сеанса, фокуса, указателя, lock-модификаторов и отмены новым
  вводом. Обычная фаза изменения текста ограничена 300 мс, вся операция —
  3,5 с. После наблюдаемого transient focus/hotkey Punto ждёт стабилизации
  клиента до 250 мс; быстрый путь ждёт 5 мс.
- После промежуточной проверки `leftctrl+space` пользовательский дефолт
  возвращён к `leftctrl+grave`. Для физической клавиши над Tab GNOME 46
  использует специальный accelerator `<Control>Above_Tab`; символьный
  `<Control>Cyrillic_io>` не принимается.
- Для GNOME 46 X11 добавлен отключённый по умолчанию compatibility shim. Он
  предотвращает X11-only freeze и удаляет только парный штатный release callback
  при вызове исходного асинхронного IBus path. Это узкий backport более нового
  поведения Shell; он не меняет уже существующие keyboard grabs. Persistent
  source и UI по-прежнему принадлежат GNOME; Wayland и другие версии не патчатся.
- GUI-выделение в Chromium преобразуется без перезаписи clipboard. Перед вводом
  Punto 30 мс подтверждает исходное точное выделение; изменение selection или
  контекста приводит к безопасному отказу. После успешного replay точный receipt
  допускает следующую word-коррекцию при сохранённом Chromium PRIMARY.
- GUI-слово сначала выделяется и фиксируется точным PRIMARY receipt.
  После desktop-перехода тот же receipt проверяется повторно до замены:
  соседний одинаковый текст не может быть принят за исходный диапазон. XInput2
  дополнительно подтверждает, что во время перехода прошли только клавиши
  собственного layout-chord; Chromium, сохранивший stale PRIMARY после внешнего
  Right, поэтому не получает вставку вместо замены.
- Mixed-layout хвост печатается через временную внутреннюю XKB-группу. Обязанность
  восстановить исходную группу регистрируется до отправки XKB-запроса и выполняется
  на всех выходах в зарезервированном участке общего дедлайна. Перед компенсирующей
  записью заново проверяются session lease, focus, pointer, locks и текущая группа.
  Отмена или перехват clipboard не затирают новый пользовательский payload.
- После первой внутренней XKB-записи обычные replay/ожидания больше не могут
  продлить работу в 100-миллисекундный резерв восстановления. Если cleanup
  переподключает XCB, финальный desktop-переход допускается только после новой
  проверки XTEST и повторной подписки на XInput2 на действующем соединении.
- Чтение очереди XInput2 ограничено 256 событиями и 5 мс. Переполнение,
  незавершённая история или ошибка соединения приводят к отказу до replay;
  посторонняя клавиша завершает проверку сразу.
- Ошибка XInput2 barrier или XIQueryVersion немедленно прекращает подготовку.
  После операции, закрывшей XCB-соединение, Punto не обращается к setup или
  другим XCB API. То же правило действует при повторной подготовке после
  cleanup/reconnect; восстановленная внутренняя группа при отказе сохраняется.
- Добавлены реальные GTK и Chromium E2E для медленных desktop-переходов,
  transient focus/selection, rich/plain clipboard, неопределённого результата
  XKB-запроса и восстановления после отказа без перезапуска.
- v2.8.12 оставлен prerelease: установленный артефакт был безопасным при отказе,
  но реальные задержки GNOME делали исправления периодически недоступными.

### v2.8.6 — Fail-closed runtime и воспроизводимый релиз

- Конфигурация разбирается строгим `yaml-cpp`: неизвестные/повторные ключи, неверные типы и небезопасные значения отклоняются целиком.
- Startup использует только системный конфиг до установления активного
  desktop-пользователя; `RELOAD` в bounded background lane читает файл через
  descriptor-rooted walk от `/`, отклоняет symlink/rename escape и публикует
  typed completion в `STATS`.
- IPC, runtime-файлы и control plane получили ограниченные очереди, строгие протоколы, безопасные права и отдельный трёхсекундный deadline для каждого shutdown-барьера.
- X11/clipboard backend переведён на bounded XCB, проверку владельца сессии и
  сериализованную generation lease. Product entry points v2.8.6 завершаются до
  X11 clipboard I/O и эмуляции клавиш: ни terminal `Ctrl+Shift+V`, ни GUI
  `Ctrl+V` вместе с наблюдаемыми selection-событиями не дают причинно связанного
  подтверждения применения подготовленного payload.
- Rich/custom clipboard не упрощается до текста: такие операции завершаются
  безопасным пропуском до смены X11 ownership.
- Desktop-сессия обнаруживается в фоне. Sound backend изолирован в отдельном
  contract-test target и не входит в product runtime безопасного режима.
- Session config reload получил generation-owned latest-intent retry: смена
  пользователя во время занятого loader не оставляет daemon на старом пути.
- Failover control plane выполняет reconcile сохранённого config до promotion:
  трёхролевой commit→crash→promotion не может переопубликовать stale snapshot
  с прежним generation, а отсутствующий config не открывает primary IPC без
  успешного fallback текущей authority.
- Tray status poll переведён с синхронного IPC на coalesced background worker;
  lifecycle процесса принадлежит статическому `systemd --user` unit.
- Запись в syslog вынесена из input/worker threads в отдельный sink с
  ограниченной очередью; переполнение учитывается в `STATS`, а зависший sink не
  блокирует ввод и аварийно завершает shutdown по трёхсекундному deadline.
- CLI и `.deb` используют `/usr/bin`, единый файл `VERSION`, неинтерактивную воспроизводимую сборку и идемпотентные lifecycle-скрипты.
- Пакет не владеет глобальным `udevmon.yaml` и не управляет чужим `udevmon.service`; пример конфигурации устанавливается отдельно для явного ручного merge.
- Mutation-компоненты (clipboard, key injection, sound, macro/history/undo)
  физически исключены из production target и проверяются только отдельными
  contract-test target.
- Загрузка словарей и сканирование `/proc` имеют строгие byte/entry/candidate/
  time limits; диагностический IPC доступен в состоянии pending, а фатальная
  инициализация завершается с детерминированным кодом.
- `SET_STATUS 0` — совместимый no-op, `SET_STATUS 1` честно отклоняется:
  управление анализом определяется только `auto_switch.enabled`, а возможность
  изменения текста в этой версии всегда выключена.
- XFixes удалён из production link graph и требуется только clipboard
  contract-тесту.
- Добавлены contract/e2e-тесты для daemon, IPC, nested-X11 GTK/VTE platform integration, конфигурации, CLI и package lifecycle.

  - hunspell (en_US.dic, en_GB.dic, ru_RU.dic)
  - wamerican-huge (~300k английских слов)
  - /usr/share/dict/* (american-english, words, russian)
- **Улучшенная логика автопереключения**:
  - Приоритет 1: Hunspell spell() с полной поддержкой словоформ
  - Приоритет 2: Hash-based проверка в загруженных словарях
  - Приоритет 3: N-граммы + анализ невалидных биграмм
  - RU→EN: требуется отсутствие невалидных EN биграмм
  - EN→RU: срабатывает при невалидных EN или перевесе ru_score
- **Примеры работающих конверсий**:
  - `lheubt` → `другие`, `ntreotq` → `текущей`, `,erd` → `букв`
  - `туеещ` → `netto` (если в словаре)
