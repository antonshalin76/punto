## История первой попытки

Первая страховка восстановила2.8.13 в18:49:04; старый timer отключён.
Старый marker `restored` означает завершённую попытку: recovery-команда
`/var/lib/punto-recovery-20261018` теперь ничего повторно не откатывает.
Она не используется для новой установки; r2 имеет отдельные markers и свежий
архив после остановки текущих writers. Старый резерв сохраняется как история.

`systemctl mask --runtime` действует только до reboot. Поэтому утверждение
«Punto остаётся выключенным» ниже относится к тому же boot: после reboot
включённый baseline backend может запуститься штатно. Всегда читать package,
markers, loaded bridge и фактические процессы, а не продолжать по старому PID.

Ниже указан порядок текущего перехода и активная аварийная команда r2.

## Переход

1. Выйти из учётной записи через меню GNOME и войти снова, сохранив X11-сеанс.
   Не перезагружать машину и не запускать вторую input chain.
2. Вернуться в этот чат и сообщить о входе. Проверяем root timer/status,
   фактически загруженный bridge и helper readiness. Только после готовности
   снимаем собственный runtime-mask и запускаем установленный `punto start`.
3. Подтверждаем настоящий ввод в собственных GTK/Chromium окнах, clipboard,
   release modifiers, next glyph, recovery и tray. До этого обычную работу
   лучше не начинать: непринятый кандидат может быть автоматически откачен.
4. После приёмки root `recover.sh --accept` под общим lock атомарно отмечает
   точный принятый payload и отключает страховочный таймер. Не делать этого
   вместо продуктовых проверок.

## Если экран чёрный или вход не удался

Штатная консоль tty3 подготовлена. Нажать **Ctrl+Alt+F3**, войти как `anton`
с обычным паролем и выполнить:

```sh
sudo systemctl start punto-recovery-20261018-r2.service
sudo systemctl status punto-recovery-20261018-r2.service --no-pager
```

Если старые файлы восстановлены, но графика ещё не вернулась:

```sh
sudo systemctl restart gdm.service
```

Последняя команда завершает графические сеансы; применять только для аварийного
возврата экрана входа. Автоматически её никто не выполняет. Восстановление
файлов само по себе не меняет уже загруженный код GNOME.
